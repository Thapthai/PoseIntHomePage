## สิ่งที่อยู่ในชุดนี้

`source/` มีโค้ด React/TypeScript, สไตล์, ข้อความไทย–อังกฤษ, รูปภาพ, ไฟล์กำหนดการทำงาน และ lockfile ของแพ็กเกจ ไม่รวม `node_modules`, ผล build, แคช, ประวัติ Git, ไฟล์ `.env`, ข้อมูลล็อกอิน หรือ token สำหรับเผยแพร่

นี่คือเว็บไซต์ประชาสัมพันธ์บริการ ไม่ใช่ซอฟต์แวร์บริหารผ้า RFID ตัวจริง และไม่มี backend สำหรับอ่านแท็กหรือบันทึกข้อมูลผ้า

## วิธีเปิดบนเครื่องโปรแกรมเมอร์

ใช้ Node.js ที่ตรงกับ `source/package.json` (อย่างน้อย 22.13.0) และ pnpm 11.19.0 แล้วเปิด terminal ในโฟลเดอร์ `source/`

```sh
pnpm install --frozen-lockfile
pnpm dev
```

เปิด Local URL ที่โปรแกรมแสดงใน terminal

ทดสอบ build:

```sh
pnpm build
```

เปิดผล build ผ่าน Wrangler ในเครื่อง:

```sh
pnpm start
```

`pnpm start` เป็น local preview ตามสคริปต์ในโปรเจกต์ ไม่ใช่คำสั่งเผยแพร่ขึ้นโดเมนจริง

### การติดตั้งแพ็กเกจ

- มี `pnpm-lock.yaml` เพื่อคงรุ่นแพ็กเกจเดิม ไม่ควรเปลี่ยนไปใช้ lockfile จาก package manager อื่นโดยไม่มีเหตุผล
- ชุดส่งต่อกำหนด `packageManager` เป็น pnpm 11.19.0 ซึ่งเป็นรุ่นที่ตรวจพบในสภาพแวดล้อมที่ใช้จัดงาน
- แก้ค่า placeholder ใน `pnpm-workspace.yaml` ให้เป็น boolean โดยอนุญาต install scripts เฉพาะ `esbuild`, `sharp` และ `workerd` ซึ่งเป็นรายการที่โปรเจกต์ระบุไว้แล้ว ผู้รับควรตรวจตามนโยบายความปลอดภัยของทีมก่อนติดตั้ง
- การติดตั้งใหม่ต้องเข้าถึง package registry และไฟล์ไบนารีของ dependency ได้
- ชุดนี้ไม่ได้รวม dependency ทั้งหมดไว้สำหรับติดตั้งแบบ offline

## แนวทางนำขึ้นระบบจริง

1. เปิดและตรวจหน้า Hotel ทั้งสองภาษา รวมเมนู ปุ่ม การตัดบรรทัด และสัญลักษณ์บนคอมพิวเตอร์/มือถือ
2. ตกลง URL ของ Hotel และ Hospital กับเจ้าของงาน โดยคงเว็บโรงพยาบาลเดิมไว้
3. ตอนนี้เมนู Healthcare ในชุดส่งงานชี้ไป `https://poseintelligence.com/` เพื่อไปเว็บเดิม หากภายหลังเปลี่ยนหน้าแรกของโดเมนนี้ ต้องแก้ลิงก์เป็น URL โรงพยาบาลจริงเพื่อไม่ให้ย้อนกลับมาหน้า Hotel
4. ปัจจุบันการตั้งค่า build ใช้ Cloudflare Workers ผ่าน Vinext/Vite ถ้าเลือกโฮสต์อื่น ให้โปรแกรมเมอร์ปรับ runtime/build/deployment ตามโฮสต์นั้น ไม่ใช่อัปโหลด ZIP โค้ดลง shared hosting แล้วใช้งานทันที
5. `.openai/hosting.json` มีรหัสโปรเจกต์ Sites เดิม ไม่ใช่รหัสผ่าน และยังจำเป็นกับ `vite.config.ts`/plugin ปัจจุบัน อย่าลบทิ้งโดยไม่ปรับ config ที่อ้างอิง และอย่าเผยแพร่ทับ Sites เดิมโดยไม่ได้รับสิทธิ์จากเจ้าของงาน
6. หากย้ายออกจาก Sites ให้ทีมปลายทางกำหนดโปรเจกต์ โฮสต์ โดเมน HTTPS และการตั้งค่าใหม่อย่างชัดเจน โดยส่งข้อมูลเข้าถึงผ่านช่องทางที่ปลอดภัยแยกจาก ZIP
